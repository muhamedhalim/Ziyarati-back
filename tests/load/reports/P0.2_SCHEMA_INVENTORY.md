# P0.2 — Schema inventory: critical integrity objects

**Date:** 2026-09-02 · **Source of truth:** `pg_catalog`, not the `migrations` table.

43 objects whose loss changes what the database will accept. Performance-only
indexes are summarised in §3 rather than listed — losing one costs latency,
not correctness.

## Legend

| column | meaning |
|---|---|
| **sync?** | does the object survive a `TYPEORM_SYNCHRONIZE=true` boot? Measured, not inferred. |
| **src** | `mig` = created by a migration · `boot` = re-created by an `OnApplicationBootstrap` `CREATE … IF NOT EXISTS` |
| **e2e** | `ziyarati_e2e` — built from the migration chain by `test/setup-e2e-db.js`. The reference schema. |
| **perf_t2 / perf / dev** | the three long-lived local databases |
| **sync-ctl** | `p02_audit` — a controlled database: migrated from empty, then booted ONCE with synchronize on |

`✓` present · `✗` **absent — PostgreSQL is not enforcing this rule**

## 3. Canonical object counts (migration-built schema, 133 migrations)

| object type | count | managed by TypeORM entity metadata? | vulnerable to synchronize |
|---|---|---|---|
| tables | 156 | mostly | tables are not dropped, but columns are (§4) |
| indexes | 454 | partially | **77 functionally lost** on one boot |
| foreign keys | 297 | yes | renamed wholesale; 10 lost, 10 gained (net 297) |
| CHECK constraints | 17 | only those declared via `@Check` | **10 lost** |
| UNIQUE constraints | 10 | only those declared via `@Unique` | 3 lost, 7 added |
| EXCLUSION constraints | 1 | yes, since P0.1 (`@Exclusion`) | survives (was lost before P0.1) |
| triggers | 1 | **no** | survives — TypeORM never manages triggers |
| extensions | 4 | partially | survive |

## 4. Column-level damage (not an object type the brief listed — found anyway)

A synchronize boot also issues **23 `DROP COLUMN`** statements and **28
`ALTER COLUMN … DROP NOT NULL`** statements. `DROP COLUMN` is not a rename —
the data in those columns is destroyed. Full lists in `P0.2_FINDINGS.md`
(SCHEMA-002, SCHEMA-003).

## 5. How to re-derive this table

```bash
# 1. disposable database, migrated from empty
createdb p02_audit && DATABASE_URL=…/p02_audit node dist/src/migrate.js run
# 2. snapshot A, boot once with TYPEORM_SYNCHRONIZE=true, snapshot B, diff
psql -d p02_audit -f snapshot.sql > A.txt
#    …boot the API against it…
psql -d p02_audit -f snapshot.sql > B.txt && diff A.txt B.txt
# 3. per-database verdict
psql "$DATABASE_URL" -f tests/load/reports/P0.2_PRODUCTION_VERIFICATION.sql
```
